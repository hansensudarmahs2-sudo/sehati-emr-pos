# QA Sweep Webapp — 2026-07-08 (Chrome DevTools)

Metode: login tiap role (owner/superadmin/dokter/perawat/apoteker/kasir/fo), fetch semua
28 URL menu owner per role → cek HTTP status (5xx? RBAC?), + render/console halaman kunci.

## Hasil inti
- **Zero 5xx** di seluruh halaman × seluruh role. Semua halaman yang diizinkan = HTTP 200.
- **Zero console error** di halaman yang dirender (dashboard, follow-up, kunjungan/antrian).
- **RBAC benar** lintas 7 role (403 rapi untuk yang tak berhak).

## RBAC per role (jumlah halaman 200 dari 28)
- superadmin: 28 OK — hanya /web/export (Raw Data Export) 403 (benar; bukan menu superadmin).
- owner: 28 OK (semua).
- apoteker_a: 12 OK. kasir_a: 11 OK. dokter_a: 8 OK. perawat_a: 7 OK. fo_a: 7 OK.
- **Follow-up (#7):** diizinkan owner/superadmin/kasir/fo; 403 untuk dokter/perawat/apoteker — persis desain.

## Fitur baru — status visual
- Halaman **Follow-up**: render sempurna (ringkasan Perlu-ditindak/Telat/Hari-ini, toggle Mingguan/Harian,
  navigasi minggu, empty-state). Kosong karena belum ada SOAP baru (wajar).
- **Antrian (warna wait)**: kartu Antri Konsultasi/Treatment/Antri Bayar render; warna baseline (antrian=0).
- **Input Rencana Kontrol di SOAP, badge menu, cetak nomor**: TIDAK bisa di-exercise live karena tak ada
  kunjungan aktif/antrian hari ini (1 visit hari ini = COMPLETED), dan sengaja TIDAK membuat data uji di DB.
  Ketiganya sudah terverifikasi di level kode + smoke sebelumnya.

## Rekomendasi
Untuk uji end-to-end fitur data-dependent (generation follow-up dari SOAP, warna merah antrian,
badge merah, cetak thermal), perlu 1 alur pasien→SOAP hidup. Bisa dilakukan manual oleh FO/dokter,
atau saya bantu seed 1 kunjungan uji bila diinginkan.

## Kesimpulan
