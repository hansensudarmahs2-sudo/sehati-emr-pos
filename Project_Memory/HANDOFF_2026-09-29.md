## 2. Pembersihan PHI dari riwayat git — WAJIB DIBACA

Ditemukan saat housekeeping. **Ter-commit sejak commit PERTAMA dan sudah ter-push ke dua
repo GitHub** (keduanya privat):

| Path | Isi |
|---|---|
| `sehati_clinic/exports/finance_pack/` (15 CSV) | **778 kunjungan** dengan `nama_pasien`, `no_rm`, `keluhan_utama` |
| `seed_data/historical_excel/*.xlsx` (3 berkas) | ~2.050 baris komisi: nama pasien, ID pasien, poliklinik **"Kulit & Kelamin"** |

`12_medical_soap_raw.csv` kebetulan **kosong** — SOAP tidak ikut bocor.
`exports/` **tidak pernah** ada di `.gitignore`: lubang terbuka, bukan kecelakaan sekali.

**Penanganan (selesai):** `git rm --cached` + `.gitignore` → `git bundle` seluruh riwayat
lama → `git filter-repo --invert-paths` atas kedua path → `push --force` ke dua remote.

**Bundle + salinan berkas PHI ada di `E:\Claude\Backups\sehati-repo\`.** Keduanya memuat
data pasien — perlakukan seperti backup DB.

### ⚠ Jebakan yang nyaris lolos

**`git filter-repo` MEMBUANG commit housekeeping beserta perubahan `.gitignore`-nya.**
Tertangkap hanya karena `git status` sesudahnya menampilkan kedua folder sebagai `??`
(tak terlacak **dan tidak diabaikan**). Kalau force-push jalan begitu saja, lubangnya
terbuka lagi dan berkasnya masuk kembali pada `git add -A` berikutnya — **persis cara
mereka masuk pertama kali.**

> **Setelah `git filter-repo`, SELALU `git status` + periksa `.gitignore` SEBELUM
> force-push.**
