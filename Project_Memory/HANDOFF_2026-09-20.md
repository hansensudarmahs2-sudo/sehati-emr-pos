## 3. PEKERJAAN BERIKUTNYA — Fase 1 Modul Racikan

Desain lengkap & keputusan terkunci ada di **`Project_Memory/DESAIN_MODUL_RACIKAN.md`** (WAJIB dibaca dulu).

### Aturan yang sudah dikunci (jangan ditanyakan ulang)
1. Butir sumber **dibulatkan KE ATAS**, dan **pasien ditagih hasil pembulatan itu** (18,75 → 19 butir). Stok juga terpotong 19.
2. Bahan **krim/topikal PRO-RATA per gram**: `harga_per_gram = harga_jual ÷ isi_kemasan` (data sudah tersedia).
3. **Biaya racik flat**: Kapsul **50.000**, Puyer **50.000**, Krim **0**.
4. Template lama (Tab SR, SR 2, SRO, STR) **dikonversi jadi Formula Racikan** — dokter tinggal ubah dosis. Kenaikan harga (±12.000 → ±19.200/kapsul) **sudah diterima**.
5. Racikan disusun **dokter di SOAP saja**; apoteker menyiapkan, tidak mengubah.
6. Hitung sekali di SOAP → **snapshot** ke resep. **Kasir tidak menghitung apa pun.**

### Rumus
```
total_mg_i = dosis_per_unit_i × N
butir_i    = total_mg_i ÷ kekuatan_sumber_i
dipakai_i  = CEIL(butir_i)                    ← ditagih & potong stok
biaya_i    = dipakai_i × harga_per_butir_i
TOTAL      = Σ biaya_i + biaya_racik(jenis)
```

### Fase 1 yang harus dibuat
- Tabel **`master_biaya_racik`** (jenis_racik unik, nama, tarif, is_active) + isi: KAPSUL 50.000, PUYER 50.000, KRIM 0.
- Tabel **`master_racikan`** (nama, jenis_racik, default_jumlah_unit, default_aturan_pakai, is_active) + **`master_racikan_bahan`** (id_produk, dosis_per_unit, satuan_dosis, urutan).
- CRUD Master Formula Racikan + konversi 4 template lama (komposisi ada di kolom `kandungan` OBM-068..071), lalu nonaktifkan 4 produk flat itu.

Fase 2 = kartu Racik di SOAP (kalkulator **server-side**), Fase 3 = kasir + potong stok + etiket.

### Komposisi 4 template untuk dikonversi
- **Tab SR** — Stenirol 8 mg + Rydian 7 mg + Metcor 2 mg
- **Tab SR 2** — Stenirol 4 mg + Rydian 5 mg + Metcor 2 mg
- **Tab SRO** — SR + Oxtin ½ tab (= 15 mg)

**Catatan penting soal tingkat keparahan**: host ini berada di balik **Cloudflare Access (Email OTP)**. Pengguna anonim mestinya dihadang di edge sebelum menyentuh `/docs`. Auditor melihatnya karena sudah lolos Access + login Superadmin. **Verifikasi dulu** dari jaringan luar tanpa cookie Access:
```bash
curl -sSI https://emr.joderma.id/openapi.json | head -5
# Harapan: 302 ke Cloudflare Access login. Kalau 200 + JSON → Access TIDAK menutup semua path → GAWAT.
```
**Perbaikan**: tambah knob di `config.py` (pola sama seperti CSP/HSTS) mis. `security_docs_enabled: bool = False`, lalu di `main.py`:
`FastAPI(..., docs_url="/docs" if settings.security_docs_enabled else None, redoc_url=..., openapi_url=...)`. Dev = aktif, produksi = mati. Murah, dampak besar.

### ❌ SALAH ALARM — 3 endpoint "tanpa security" ternyata TERLINDUNGI
Diverifikasi di kode, ketiganya punya `current_user: CurrentUser` **dan** dependency role:
- `POST /api/v1/pasien/baru` → `api/v1/pasien.py:177` (`_REGISTER_ROLES`)
- `POST /api/v1/kunjungan/lama` → `api/v1/kunjungan.py:161` (`_DAFTAR_ROLES`)
- `POST /api/v1/dokter/input-medis` → `api/v1/dokter.py:57` (`_INPUT_MEDIS_ROLES`)

`CurrentUser = Annotated[MasterStaf, Depends(get_current_user)]` (`core/deps.py:87`), dan `get_current_user` bergantung pada `oauth2_scheme = OAuth2PasswordBearer(...)` (`deps.py:21,40`) dengan `auto_error` default → tanpa token = **401**. Jadi tidak ada lubang; absennya `security` di skema itu artefak pembacaan, bukan bug. **Tidak perlu tindakan.**

### ⚠️ BENAR TAPI RINGAN — 3 endpoint Finance tanpa auth

Risiko nyata hanya kebocoran rancangan lewat `/openapi.json`, yang otomatis tertutup begitu docs dimatikan.
